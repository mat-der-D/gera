# gera

**AI が生成した Markdown 文書を読むためのデスクトップビューア。**編集機能も持つが、それは従である。**ほとんどビューアで、おまけで編集機能がある**——これが gera の立ち位置である。

## 名前について

ゲラとは校正刷りのこと。組版を終えて刷り上がり、これから読み合わせて赤を入れる紙を指す。

AI の出力はゲラである。すでに形になっていて、体裁も整っている。しかし、そのままでは出せない。

## 何を解こうとしているか

**痛みは二つある。**

- **読みにくい**——VS Code の Markdown Preview は目に優しくなく、好みの見た目にカスタマイズする口もない
- **探せない**——AI が書く文書は膨大で、知りたいことが書いてある場所を見つけるだけでも大変である

**比較対象は VS Code、速度の基準は Zed。**「Zed ぐらいサクサク動くソフトウェアで、Markdown の確認がサクサクでき、編集したいときに必要な箇所を自由に編集できる」ことを目指す。

前者には版面とユーザー CSS が、後者にはアウトラインと文書内検索が効く。

## 優先順位

1. **起動速度**（第一）
2. **動作速度**（同じく第一）
3. **シンプルさ**（二番目。覚えるべき概念が少ないこと）

実測（2026-09-02、Ubuntu 24.04 / ウォーム起動 n=6 中央値）:

| 最初の描画まで | gera | Zed | VS Code |
|---|---|---|---|
| | **0.274 s** | 0.444 s | 0.707 s |

バイナリ 14.8 MB、実メモリ 481 MB（VS Code は 216 MB / 6,261 MB）。測定条件は [docs/DESIGN.md](docs/DESIGN.md) 第 5 節を参照。

## 二つのモード（対等ではない）

同一画面を切り替える。**閲覧モードが本体で、編集モードは従である。**

| モード | 位置づけ | 表示 | 対応する作業 |
|---|---|---|---|
| 閲覧 | **本体** | 完全に描画する。表・数式・コードブロック | 読み合わせ、調べ物 |
| 編集 | 従 | 記法を残したまま装飾のみ当てる | 削除と並べ替え |

`Mod+E` で切り替える。**切り替え前に見ていた箇所が、切り替え後も画面に見えている**——これを両方向で満たす。閲覧モードでブロックをダブルクリックすれば、その場で局所編集できる。

## 技術

- **Tauri 2** — アプリ基盤
- **CodeMirror 6** — エディタコア
- **素の TypeScript + Vite** — フレームワークは入れない
- **markdown-it + DOMPurify** — 閲覧モードの描画
- **KaTeX**（`@vscode/markdown-it-katex`）— 数式

Rust 側の責務はファイル入出力、ダイアログ、ウィンドウ状態、コマンドライン引数のみ。
