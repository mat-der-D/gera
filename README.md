# gera

**AI が生成した Markdown 文書を読むためのデスクトップビューア。**編集機能も持つが、それは従である。**ほとんどビューアで、おまけで編集機能がある**——これが gera の立ち位置である。

## 名前について

ゲラとは校正刷りのこと。組版を終えて刷り上がり、これから読み合わせて赤を入れる紙を指す。

AI の出力はゲラである。すでに形になっていて、体裁も整っている。しかし、そのままでは出せない。

## 何を解こうとしているか

**痛みは二つある。**

- **読みにくい**——VS Code の Markdown Preview は目に優しくなく、好みの見た目にカスタマイズする口もない
- **探せない**——AI が書く文書は膨大で、知りたいことが書いてある場所を見つけるだけでも大変である

**比較対象は VS Code、速度の基準は Zed。**「Zed ぐらいサクサク動くソフトウェアで、Markdown の確認がサクサクでき、編集したいときに必要な箇所を自由に編集できる」ことを目指す。

前者には版面とユーザー CSS が、後者にはアウトラインと文書内検索が効く。

## 優先順位

1. **起動速度**（第一）
2. **動作速度**（同じく第一）
3. **シンプルさ**（二番目。覚えるべき概念が少ないこと）

実測（2026-09-02、Ubuntu 24.04 / ウォーム起動 n=6 中央値）:

| 最初の描画まで | gera | Zed | VS Code |
|---|---|---|---|
| | **0.274 s** | 0.444 s | 0.707 s |

バイナリ 14.8 MB、実メモリ 481 MB（VS Code は 216 MB / 6,261 MB）。測定条件は [docs/DESIGN.md](docs/DESIGN.md) 第 5 節を参照。

## 二つのモード（対等ではない）

同一画面を切り替える。**閲覧モードが本体で、編集モードは従である。**

| モード | 位置づけ | 表示 | 対応する作業 |
|---|---|---|---|
| 閲覧 | **本体** | 完全に描画する。表・数式・コードブロック | 読み合わせ、調べ物 |
| 編集 | 従 | 記法を残したまま装飾のみ当てる | 削除と並べ替え |

`Mod+E` で切り替える。**切り替え前に見ていた箇所が、切り替え後も画面に見えている**——これを両方向で満たす。閲覧モードでブロックをダブルクリックすれば、その場で局所編集できる。

## 技術

- **Tauri 2** — アプリ基盤
- **CodeMirror 6** — エディタコア
- **素の TypeScript + Vite** — フレームワークは入れない
- **markdown-it + DOMPurify** — 閲覧モードの描画
- **KaTeX**（`@vscode/markdown-it-katex`）— 数式

Rust 側の責務はファイル入出力、ダイアログ、ウィンドウ状態、コマンドライン引数のみ。

## 状態

**初版の要件は揃った**（実装順序 1〜9 完了。[docs/DESIGN.md](docs/DESIGN.md) 第 12 節）。閲覧・編集の両モード、数式、コマンドライン引数とファイル関連付け、アウトライン、文書内検索、ユーザー CSS、外部変更への追随、キー一覧（`F1`）まで入っている。

**残るのは配布と、Linux 以外の実機での確認である。**Windows 版・macOS 版・Linux 版を GitHub Actions で毎回組んでいるが（`.github/workflows/build.yml`）、**Windows と macOS は実機で動かして確かめてはいない**（第 15 節）。

初版に入れない機能（Mermaid、シンタックスハイライト、ファイル横断検索など）は**後から足すつもりのものであって、却下したものではない。**

設計の詳細・実測値・判断の根拠は [docs/DESIGN.md](docs/DESIGN.md) にある。

## 配布物（Windows・macOS・Linux）

**GitHub Actions でビルドしている。**Windows と macOS は開発機が Linux のためここでしか作れない。**Linux 版は手元でも作れるが、渡すときに三 OS 分が揃っているほうが楽なので、同じところで作っている。**

- **試用版**——[Actions](../../actions/workflows/build.yml) の最新の実行を開いてアーティファクトを落とす。**GitHub にログインしていないと落とせない**
- **公開版**——[Releases](../../releases)。タグを打つと下書きができ、確認してから公開する

| | アーティファクト |
|---|---|
| Windows | `gera-windows-installer`（インストーラ）/ `gera-windows-exe`（素の実行ファイル） |
| macOS | `gera-macos-dmg`（ディスクイメージ）/ `gera-macos-app`（素のアプリ。zip） |
| Linux | `gera-linux-deb`（Ubuntu/Debian 系）/ `gera-linux-appimage`（入れずに動く単体ファイル） |

**macOS 版はユニバーサルバイナリである**——Apple Silicon と Intel の両方で動く。

**Linux 版は x86_64 のみで、Ubuntu 24.04 以降（glibc 2.39 以降）が要る。**22.04 では起動しない——**Linux のバイナリは、組んだ機械の glibc より古い環境では動かない**ためで、AppImage でもここは変わらない（WebKitGTK は同梱するが libc はしない）。`.md` の関連付けとメニュー登録が付くのは deb のほうである。AppImage は落としたあと `chmod +x` が要る。

### 署名していない

**Windows**——初回起動時に SmartScreen が「WindowsによってPCが保護されました」と警告を出す。**「詳細情報」→「実行」**で進める。

**macOS**——Gatekeeper が止め、**ダブルクリックでは開けない。壊れているのではない。**

1. まず一度、普通に開こうとする（止められる）
2. **システム設定 → プライバシーとセキュリティ**を開き、下へスクロールして**「このまま開く」**を押す
3. もう一度警告が出るので**「開く」**を押す

以降は普通に開ける。**右クリック →「開く」は macOS 15 (Sequoia) 以降では通らない**（Apple が塞いだ。古い macOS では通る）。端末から外す `xattr -d com.apple.quarantine /Applications/gera.app` は**未検証**。

**Linux**——署名の仕組みが無いので、警告も回避手順も無い。deb はそのまま入り、AppImage は `chmod +x` して実行するだけである。

### ユーザー CSS の置き場

**macOS は `~/Library/Application Support/dev.smoothpudding.gera/user.css` である。**Tauri の `app_config_dir()` の定義から導いた推定だったが、**2026-09-07 に実機で当たっていることが確かめられた**——このパスに置いた `user.css` が反映されたという報告である。

**Windows の `%APPDATA%\dev.smoothpudding.gera\user.css` は、まだ推定のままである。**同じ `app_config_dir()` から導いた値であって、**実機では未検証である**（[docs/DESIGN.md](docs/DESIGN.md) 第 15 節）。確認したらここを直す。

### macOS で確かめること

**2026-09-07 に、macOS で gera が動き、`Cmd+,` で `user.css` が読み直せるところまで確かめられた。**置き場が当たっていたのはそのためである（一つ上）。**`Cmd+,` は「設定…」のショートカットなので OS に奪われると見ていたが、外れた——奪われずに gera に届く。**確かめられたのはそこまでで、次は未検証のまま残る。

| 項目 | いま分かっていること |
|---|---|
| 日本語 IME | WKWebView なので Linux の候補窓のずれ（[WebKit bug 218148](https://bugs.webkit.org/show_bug.cgi?id=218148)）は出ないはず。**理屈だけ** |
| フォント | **ヒラギノには届かない見込みである。**macOS には游明朝・游ゴシックが標準で入っており、書体スタック（`src/style.css`）ではヒラギノより前に並ぶ。**出ているのが游明朝かヒラギノ明朝かを見たい。**あわせて、**コードブロックの中の日本語**——`--font-mono` の四つは macOS にどれも無いので、`monospace` に落ちる |
| `Cmd+R` / `Cmd+F` / `Cmd+Shift+O` / `Cmd +` `Cmd -` `Cmd 0` | **奪われないか。`Cmd+,` は奪われなかったが、それだけでは他のキーの根拠にならない** |
| `F1` | キーの一覧。**機種によっては `Fn+F1` が要る** |
| キーの表記 | `Cmd` に出し分ける処理は入っているが未検証 |
| `.md` の関連付け | ダブルクリックして gera で開くか |
| タイトルバー | Linux のネイティブ Wayland では機能しない（既知）。macOS では効く見込みだが未検証 |
| ビルドそのもの | **GitHub Actions では成功している**（2026-09-04）。**その成果物が実機で起動することも 2026-09-07 に確かめられた** |
