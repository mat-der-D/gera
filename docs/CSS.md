# 見た目を自分で変える

gera の閲覧モードは、**素の HTML と、数えるほどのクラス名**でできている。CSS を書けば、既定の版面をいくらでも差し替えられる。設定画面は無い（設計文書 第9-4節）。

**ここに挙げたクラス名と CSS 変数は公開 API である。**実装の都合で勝手に変えない。

---

## 書いた CSS を読ませる

**ファイルを一つ置くだけである。**名前は `user.css`、置き場はここ。

| OS | 置き場 |
|---|---|
| **Linux** | `~/.config/dev.smoothpudding.gera/user.css` |
| **Windows** | `%APPDATA%\dev.smoothpudding.gera\user.css` |

**フォルダが無ければ作る。**`user.css` が無くても gera は普通に動く（無いことは失敗ではない）。

- **書き換えたら `Mod+,`**（Linux と Windows では `Ctrl+,`、macOS では `Cmd+,`）。**起動し直さずにその場で反映される。**多くの editor で「設定」を開く綴りに揃えてあり、**gera にとっての設定はこの `user.css` ただ一つ**である
- **押すと帯が出て、置き場のフルパスが表示される。**反映されたときも、ファイルが無かったときも、読めなかったときも出る。**どこに置けばよいか迷ったら、とりあえず押せばよい**——画面がそのパスを教える
- **設定画面は無い**（設計文書 第9-4節）。**やることは「ファイルをここに置く」だけである**
- **自動では追随しない。**gera は `user.css` を監視していないので、書き換えたら `Mod+,` を押すこと
- **gera 自身を開発しているときは別である。**`npm run dev` で `src/viewer.css`（閲覧モードの版面）・`src/style.css`（色と書体）・`src/outline.css`（見出しの一覧）・`src/find.css`（文書内検索）を直接いじれば、保存した時点で反映される。**利用者として見た目を変えるだけなら `user.css` で足りる**

### そのまま使える三枚——`presets/`

**リポジトリの `presets/` に既製の CSS が三枚ある。中身を読まずに使ってよい。****どれか一枚を `user.css` という名前で上の置き場へコピーするだけ**である。

| ファイル | 何をするものか |
|---|---|
| `presets/gothic.css` | **本文の書体を明朝からゴシックにする。**明朝が読みづらい人向け。ゴシックは字面が大きいので行間も少し足してある |
| `presets/large.css` | **字を大きくする**（閲覧 20px / 編集 19px）。**行長も詰めてある**ので、一行の字数は既定のまま保たれる |
| `presets/wide.css` | **一行を長くし、余白を詰める。表とコードの多い文書向け**である。地の文だけの文書では逆に読みにくい |

**二枚以上を組み合わせたければ、中身をつなげて一つの `user.css` にすればよい。**特別な仕組みは要らない。

**三枚とも、この文書の「触らないほうがよいもの」を守って書いてある。**自分で書き足すときも同じ線を守ること。

## いちばん短い例——明朝をやめる

既定は明朝で組んである。読みづらければ、**これだけで全部ゴシックになる。**

```css
:root {
  --font-serif: "Yu Gothic", YuGothic, "Noto Sans CJK JP", "Hiragino Sans", Meiryo, sans-serif;
}
```

`--font-serif` は「明朝を入れる変数」ではなく「**本文の書体**を入れる変数」である。ここにゴシックを入れれば本文がゴシックになる。

書体だけでなく、**大きさと行間まで好みに合わせる**なら次のように書く。ゴシックは明朝より字面が大きいので、同じ行間だと詰まって見える。

```css
:root {
  --font-serif: "Yu Gothic", YuGothic, "Noto Sans CJK JP", sans-serif;
  --font-size-view: 16px;   /* 閲覧モードの基準。既定は 17px */
}
.gera-doc {
  line-height: 2.1;         /* 既定は 1.95 */
}
```

**大きさは `.gera-doc { font-size: … }` ではなく `--font-size-view` で指定する。**前者で書くと `calc(var(--font-size-view) * var(--font-scale))` ごと上書きしてしまい、**`Mod +` / `Mod -` が効かなくなる。**理由は次節に書いた。

## 色と書体——CSS 変数

`src/style.css` が持っている変数で、**編集モードと閲覧モードの両方に効く。**`:root` に上書きを書く。

| 変数 | 何に使われるか |
|---|---|
| `--font-serif` | **本文の書体。**既定は明朝 |
| `--font-sans` | 通知の帯などの補助的な文字 |
| `--font-mono` | コード、インラインコード、数式の変換に失敗したところ |
| `--bg` | ウィンドウの地色 |
| `--fg` | 本文の文字色 |
| `--dim` | 薄い文字（`h6`、取り消し線、通知の帯） |
| `--rule` | 罫線（`h2` の下、`hr`、表の枠、コードの枠、引用の縦線） |
| `--accent` | リンクの色、箇条書きの点、チェックボックス |
| `--code-bg` | コードと表の見出し行の地色 |
| `--sel` | 選択範囲（編集モード） |
| `--zebra` | 表の偶数行の地色 |

ダークモードは OS の設定（`prefers-color-scheme`）に従って変数が入れ替わる。**片方だけ変えたいなら、メディアクエリの中に書く。**

```css
@media (prefers-color-scheme: dark) {
  :root { --bg: #101010; --fg: #d8d8d8; }
}
```

## 字の大きさ——基準と倍率

字の大きさは**キーボードでも変えられる**（`Mod +` / `Mod -` / `Mod 0`）。**利用者 CSS とキーボード操作が同じ値を奪い合わないよう、基準と倍率を別の変数に分けてある。**実際の指定は次の 2 行だけである（`src/style.css` と `src/viewer.css`）。

```css
.gera-doc       { font-size: calc(var(--font-size-view) * var(--font-scale)); }
#app .cm-editor { font-size: calc(var(--font-size-edit) * var(--font-scale)); }
```

| 変数 | 既定 | 意味 | 利用者 CSS |
|---|---|---|---|
| `--font-size-view` | `17px` | **閲覧モードの基準** | **ここを上書きする** |
| `--font-size-edit` | `16px` | **編集モードの基準** | **ここを上書きする** |
| `--font-scale` | `1` | 倍率。`Mod +` / `Mod -` / `Mod 0` だけが触る | **触らないこと** |

- **上書きしてよいのは基準（`--font-size-view` / `--font-size-edit`）だけである。**倍率を CSS で固定すると、`Mod +` / `Mod -` が書き込んだ値が打ち消され、**キーボードで大きさが変わらなくなる**
- **`Mod 0` は倍率を 1 に戻すだけで、基準には触れない。**つまり戻り先は「**利用者が CSS で決めた大きさ**」であって、gera の既定 17px ではない。**利用者の設定を消す「戻す」は不具合である**という判断による
- **基準が二つに分かれているのは、閲覧と編集で書体が違うからである。**閲覧は明朝 17px、編集はゴシック 16px で、それぞれの書体の字面に合わせた寸法である。**片方に揃えるとどちらかの版面が崩れる**
- **見出し・コード・表・数式の寸法はすべて `em` の相対指定である。**したがって**基準を変えれば版面全体が比例して動く。**個別の要素を一つずつ直す必要はない

**友人向けの実用例——ゴシックにして、好みの大きさにする。**

```css
:root {
  /* 種類: 本文の書体をゴシックにする */
  --font-serif: "Yu Gothic", YuGothic, "Noto Sans CJK JP", "Hiragino Sans", Meiryo, sans-serif;
  /* 大きさ: 基準だけを動かす。倍率（--font-scale）には触らない */
  --font-size-view: 18px;   /* 既定は 17px */
  --font-size-edit: 17px;   /* 既定は 16px */
}
.gera-doc {
  line-height: 2.1;         /* ゴシックは字面が大きいので行間を足す。既定は 1.95 */
}
```

これを書いた上でも `Mod +` / `Mod -` は効き、`Mod 0` は 18px に戻る。

## 閲覧モードの構造

閲覧モードの DOM はこの形をしている。**トップレベルのブロックが平らに並ぶ**だけで、入れ子の器は無い。

```html
<div class="gera-view">          <!-- スクロールする器。外側の余白はここ -->
  <article class="gera-doc">     <!-- 本文。書体・行長・行間・文字色はここ -->
    <h1 id="見出しの綴り" data-line="0" data-line-end="1">…</h1>
    <p data-line="2" data-line-end="3">…</p>
    <ul data-line="4" data-line-end="7">
      <li class="gera-task"><input type="checkbox" disabled> …</li>
    </ul>
    <div class="gera-table" data-line="…">
      <table>…</table>
    </div>
    <pre data-line="…"><code>…</code></pre>
    <div class="gera-math" data-line="…">   <!-- $$…$$ の別行立て -->
      <p class="katex-block"><span class="katex">…</span></p>
    </div>
  </article>
</div>
```

### クラス名

| 名前 | 何か | よくある上書き |
|---|---|---|
| `.gera-view` | スクロールする器 | 上下左右の余白（`padding`） |
| `.gera-doc` | 本文全体 | 書体、行長（`max-width`）、行間、文字の大きさ |
| `.gera-table` | 表を包む箱 | 表だけの横スクロールをやめる、余白を変える |
| `.gera-math` | `$$…$$` の別行立て数式を包む箱 | 余白、左寄せにする |
| `.gera-task` | `- [ ]` で書いたタスクの項目（`li` に付く） | チェックボックスの位置 |
| `.gera-outline` | 見出しの一覧（`Mod+Shift+O`）が出るときに画面全体を覆うオーバーレイの器 | 覆いの濃さ、一覧を出す位置（`padding`） |
| `.gera-outline-box` | 一覧の箱 | 幅（`max-width`）、枠、影、角の丸み |
| `.gera-outline-input` | 絞り込みの入力欄 | 書体、大きさ、余白 |
| `.gera-outline-list` | 一覧本体（縦にスクロールする） | 書体、大きさ |
| `.gera-outline-item` | 見出し一件。`data-depth="0"`〜`"5"` が付く | 字下げの幅、行の高さ |
| `.gera-outline-selected` | いま選んでいる一件（`.gera-outline-item` に足される） | 選択の色、左端の印 |
| `.gera-outline-mark` | 打った文字が当たった箇所 | 当たりの色、太さ |
| `.gera-outline-empty` | 該当なし／見出しなしのときの表示 | 文字色、余白 |
| `.gera-find` | 文書内検索（`Mod+F`）の入力欄の箱。**画面の右下に固定で浮く** | 出す位置（`right` / `bottom`）、枠、影、角の丸み |
| `.gera-find-input` | 検索語の入力欄 | 書体、大きさ、幅 |
| `.gera-find-count` | 「3 / 13」の件数表示 | 文字色、大きさ、幅 |
| `.gera-find-none` | 0 件のときに件数側に足される印 | 文字色 |

**`data-depth` は絶対の見出し番号ではない。**その文書の中で**最も浅い見出しからの差**である（`##` から始まる文書が普通にあるので、絶対の番号で字下げすると全部が一段下がって字下げの意味が消える）。6 段で頭打ちにしてある。字下げを変えるならこう書く。

```css
.gera-outline-item[data-depth="1"] { padding-left: 3rem; }   /* 既定は 2.1rem */
```

**一覧の寸法はすべて `rem` で書いてあり、`--font-scale`（`Mod +` / `Mod -`）の影響を受けない。これは意図した設計である。**倍率が動かすのは**版面**——読んでいる本文の大きさ——であって、道具の大きさではない。**本文を大きくしたときに一覧まで太ると、一画面に入る見出しの本数が減って探しにくくなり、目的が逆を向く。**一覧だけを大きくしたいなら、`.gera-outline-list` と `.gera-outline-input` の `font-size` を直接書けばよい。

### 文書内検索（`Mod+F`）

**検索の入力欄は、見出しの一覧と違って本文を覆わない。**覆いを敷かず、**画面の右下に小さく浮かせてある**（既定は `right: 1rem; bottom: 1rem;`）。**検索は当たった箇所を見ながら使う道具なので、本文を隠してはならない。**右**下**なのは、**飛び先が画面の上端に来る**ためで、下に居れば当たりを自分で隠さない。**出す位置を変えるなら、この二つを崩さないほうがよい。**

```css
.gera-find { left: 1rem; right: auto; }   /* 左下に出す */
```

- **箱の地色・枠・影は変数から取っている**（`var(--bg)`、`var(--rule)`、影は `var(--fg)` を薄めたもの）。**覆いが無いぶん、本文の上に浮いていることを示すのは影だけである**——消すと本文と地続きに見える
- **入力欄と件数の文字はゴシック**（`var(--font-sans)`）である。**明朝で組まれるのは本文だけで、それがモード表示も兼ねている**
- **件数（`.gera-find-count`）には `font-variant-numeric: tabular-nums` と最小幅が入っている。**桁が変わるたびに入力欄まで左右に揺れると、打っている最中に目が引っ張られるためである。**幅を狭めるときはこの点に注意する**
- **`.gera-find-none` は 0 件のときだけ件数側に足される。**色を変えているのは、0 件と「1 / 13」を一目で見分けるためだけである
- **移り変わり（`transition` / `animation`）を足さないこと。**出入りにアニメーションを付けると、そのあいだ毎フレーム描画が走る。**アイドル中に 60fps でフレームが出る不具合を直したばかりであり**（設計文書 第5-10節、この文書の「触らないほうがよいもの」）、**同じ費用をここで払い直すことになる**

**寸法はすべて `rem` で書いてあり、`--font-scale`（`Mod +` / `Mod -`）の影響を受けない。**見出しの一覧と同じ理由である——**倍率が動かすのは版面であって、道具ではない。**

#### 当たりの色——`::highlight()`

**当たりに色を付けるのに `<mark>` は使っていない。**CSS Custom Highlight API を使い、**本文の DOM をいっさい書き換えない**（設計文書 第9-2節）。したがって**書き方が通常のクラスと違う。**セレクタは疑似要素であり、**HTML の中を探しても対応する要素は無い。**

```css
/* 当たり全部（薄い）。既定はアクセント色を 28% に薄めたもの */
::highlight(gera-find) {
  background-color: color-mix(in srgb, var(--accent) 40%, transparent);
}

/* いま選んでいる 1 件（濃い）。既定は地色 var(--accent) ／ 文字色 var(--bg) */
::highlight(gera-find-current) {
  background-color: #c00;
  color: #fff;
}
```

- **`::highlight()` に書けるプロパティは限られている。**通るのは**文字色・地色・文字装飾（`text-decoration`）・影（`text-shadow`）・縁取り（`-webkit-text-stroke`）**の類だけで、**余白・枠・太さ・大きさは効かない。**当たりを「太字にする」「枠で囲う」といった指定はできない
- **`gera-find` は読む邪魔をしない濃さに留めること。**当たりが何十件もある文書で全部が濃いと、**本文が読めなくなる。**濃くしてよいのは `gera-find-current` の側だけである
- **色が付くのは、いま画面に入っているブロックの当たりだけである。**画面外は色が付かないが**当たりとしては数えられている**（件数には入る）。これは節約ではなく、**`content-visibility: auto` の外にレンジを作ると無関係な段落が丸ごと塗られるため**の回避である（設計文書 第5-12節）。**CSS 側で変えられるものではない**
- **編集モードでは `::highlight()` を使っていない。**現在の当たりを CodeMirror の選択範囲で示すだけなので、**ここでの指定は閲覧モードにしか効かない**

**これ以外の見た目は、素の要素名で書ける。**`.gera-doc h2`、`.gera-doc p`、`.gera-doc blockquote`、`.gera-doc pre`、`.gera-doc table`、`.gera-doc a`、`.gera-doc details` のように、`.gera-doc` の下に普通のセレクタを並べればよい。gera の側で独自のクラスを増やしていないのは、**覚えるべき名前を増やさないため**である。

### KaTeX の名前

数式は KaTeX が描くので、その中のクラス名は KaTeX のものである（`.katex`、`.katex-block`、`.katex-display`、`.katex-error` など）。gera が決めた名前ではないので、**KaTeX の版が上がると変わりうる。**変えてよいのは大きさくらいにしておくのが安全である。

```css
.gera-doc .katex { font-size: 1.15em; }   /* 既定は 1.08em */
```

### `data-line` と `id`

- `data-line` / `data-line-end` は、そのブロックが元の Markdown の何行目から何行目までかを表す（0 始まり、終端は含まない）。編集モードと行き来したときに同じ場所へ戻るために使っている。**見た目のために使うものではないが、セレクタとしては使える**
- 見出しの `id` は GitHub と同じ綴り（小文字化し、ASCII の記号を落とし、空白を `-` にする）。`[…](#見出し)` のリンクがこれを目指して飛ぶ

## 触らないほうがよいもの

**`content-visibility` と `contain-intrinsic-size` を消さないこと。**`.gera-doc > *` に付いていて、画面の外にあるブロックを描く仕事から外している。数式の多い文書では、これが有るかどうかで最初の一枚が出るまでが 800 ms と 1,000 ms 以上に分かれる。

うっかり消してしまうのは、次のような書き方である。

```css
/* これをやると content-visibility ごと上書きされる */
.gera-doc > * { contain: none; }
```

余白や色を変えたいだけなら、`content-visibility` に触れない書き方をすればよい。

```css
.gera-doc > p { margin: 1.2em 0; }   /* こちらは安全 */
```

**`contain-intrinsic-size` を px で書き直さないこと。**gera は `.gera-doc > *` および見出し・箇条書き・コード・表・数式の各ブロックに、**`em` で**推定の高さを与えている（`.gera-doc > h1` なら `auto 1.53em` のように、要素ごとに違う値）。

**`em` なのは、字の大きさが二方向に動くからである。**基準（利用者 CSS の `--font-size-view`）でも倍率（`Mod +` / `Mod -`）でも `.gera-doc` の `font-size` は動く。`em` は自分の `font-size` に対する比なので、**どちらが動いても推定が同じ比のまま付いてくる。**px で固定すると**拡大したときだけ推定が小さいまま取り残され**、画面外の文書が実際より短く見積もられる。**結果としてスクロールバーの長さが縮み、送るたびに位置が跳ねる。**

推定を消してしまうのも同じ害を招く。`contain-intrinsic-size` の無い `content-visibility: auto` は画面外の高さを 0 と見なすため、**文書全体の高さが縮んでスクロールが暴れる。**

**`::-webkit-scrollbar` の定義を消さないこと。**`src/style.css` に一式（`*::-webkit-scrollbar`、`-track`、`-thumb`、`-thumb:hover`、`-corner`）が書いてある。**これは見た目のためではなく、バグの修正である。**

```css
/* これをやると、アイドル中も 60fps で描画し続けるバグが戻る */
*::-webkit-scrollbar { display: none; }
```

WebKitGTK の既定のスクロールバーは重ね置き（オーバーレイ）で、**出てから消えるまでを 3 秒かけて描き直す。そのあいだ毎フレーム描画が走る。**`::-webkit-scrollbar` を一つでも書くと、WebKit は**CSS で描くスクロールバー**に切り替える。**こちらは薄くなるアニメーションを持たないので、静止していればフレームが出ない**（設計文書 第5-10節）。定義を消すと既定に戻り、**バグが再発する。**

**色や幅を変えるのは構わない。**既定は幅 10px、色は `var(--rule)`（つまみ）と `var(--dim)`（つまみにポインタが載ったとき）である。

```css
*::-webkit-scrollbar { width: 14px; }              /* 太くする */
*::-webkit-scrollbar-thumb { background: var(--accent); }
```
